# Koda Phase 4E: 插件与更新供应链

- 状态：本地签名包验证、受管理安装、手动启停、上一版本回滚、已签名包目录发布、HTTPS 签名目录发现、确切版本下载和手动选择较新稳定版已实现。定时自动更新、信任根轮换与崩溃点验收未完成。
- 范围：本轮只处理 macOS；Linux、Windows 发布暂缓。公开发布仍需要 Apple Developer 签名与公证凭据。

## 信任边界

现有 `plugins.json` 是所有者手工审查的本地命令配置。它的配置摘要不能证明命令文件来自受信发布者。受管理插件必须使用独立包目录：`manifest.json` 声明插件 ID、版本、入口和每个负载文件的字节数及 SHA-256。发布者用 Ed25519 对带域分隔符的清单摘要签名；所有者在本机显式信任发布者公钥。下载的清单或包不能自行添加信任根。

验证时限制文件数、单文件和总字节数，检查清单内路径顺序、重复及穿越，拒绝符号链接、硬链接、特殊文件和未列出的文件。入口必须在文件清单中。安装先复制到受管理目录并重新验证，启用和每次 Turn 加载前再次验证；新包默认停用，更新保留上版，回滚也保持停用。对已安装插件的包内容更新会在暂存目录执行一次无凭据、无工具调用的协议初始化，检查版本与签名清单一致，再复核文件并切换；首次安装不执行插件。崩溃点验收仍未完成。现有手工插件继续按原配置运行，不能被误标为已签名插件。

## 交付顺序与验收

1. **本地包验证：** 使用所有者给出的公钥验证签名和完整文件清单；错钥、改字节、额外文件、链接、路径穿越均失败。测试使用临时密钥和临时目录，不依赖网络。
2. **受管理安装：** 从已验证目录复制到版本化暂存目录，复核摘要后原子激活；保存来源、公钥 ID、包摘要。插件加载器只从已验证的受管理目录派生命令与入口。
3. **发现及启停：** 注册表索引有独立签名与过期时间；发现不执行代码。用户审查能力和准确工具效果后才能启用。禁用不删除已安装版本。
4. **更新与回滚：** 新版本在暂存区验证和初始化，成功后原子切换；失败保持或恢复旧版本。崩溃恢复检查操作日志与激活指针，绝不运行未完成验证的版本。
5. **macOS 应用更新：** 更新源绑定签名发布元数据、归档摘要和来源提交；下载后复核包与运行时完整性，再明确执行安装。公开自动更新必须额外通过代码签名、公证、Gatekeeper 与签名身份连续性检查。无 Apple Developer 凭据时只允许内部预览安装和验证，不宣称公开自动更新可用。

Phase 4E 验收需要恶意清单、回滚、断电点、信任根轮换和已安装包篡改测试。Phase 4F 再覆盖整条发布及远程运行矩阵。

当前目录 v1 为 HTTPS JSON：`schema_version: 1`、严格 UTC 的 `generated_at` 与 `expires_at`、按 ID／版本排序的 `packages`（每项含 `id`、`version`、相对 `manifest_path`、`manifest_sha256`），以及同一发布者 Ed25519 签名。签名覆盖带目录专用域分隔符的规范 JSON 摘要。客户端拒绝过期目录、跨来源 URL、重定向和超出大小上限的响应；下载文件后仍按签名包规则复核。安装状态保存目录 URL 与摘要。手动 `plugin update` 选择高于当前版本的最新稳定版并保持停用；定时检查和自动启用尚未实现。

发布者把已签名包放在 `ID/版本/` 下，使用受保护的 Ed25519 私钥运行 `plugin publish-catalog`。命令先逐包核验签名与负载，再生成有期限的目录并在本地原子替换 `catalog.json`。发布者负责把整个目录部署到 HTTPS 静态源；客户端仍独立校验目录与每个包。私钥不会写入目录或安装记录。
